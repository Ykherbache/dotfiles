# Chapter 10 — The Whole XP Team

Everyone is roped together walking up a glacier. It doesn't matter who's first — what matters is knowing you're roped together.

## Roles

**Testers** — Shift left: help customers write automated system-level tests before implementation. Ask "but what if login fails three times?" Amplify communication.

**Interaction Designers** — Choose metaphors, write stories, evaluate usage. Work with customers continuously, not in a phase. "Specify a little bit up front and refine throughout."

**Architects** — Look for and execute large-scale refactorings, write stress tests, implement stories. Sign up for programming tasks like everyone else. "Conquer and divide" — start small, find fracture lines. Communicate architecture through tests, not specifications.

**Project Managers** — Facilitate communication in and out. Team historians. Translate cards-on-wall into whatever format the org expects. "The power gained from being an effective facilitator exceeds that of being a controller of information."

**Product Managers** — Write stories, pick themes and stories, answer implementation questions. Stories should be sequenced for business reasons, not technical. System should be "whole" at end of first week.

**Executives** — Provide courage, confidence, accountability. Monitor improvement. Two key metrics: (1) post-development defect count, (2) time from investment to first revenue. "You don't make a car go faster by grabbing the speedometer needle."

**Technical Writers** — First to see features (early feedback). Create closer user relationships. Documentation one week behind stories, then same week. Monitor documentation usage — stop writing what no one reads.

**Users** — Write and pick stories, make domain decisions. Speak for the broader community.

**Programmers** — Estimate, break stories into tasks, write tests, write code, automate, improve design. Need good social and relationship skills.

## HR Considerations
- **Reviews**: XP transparency gives plenty of individual evaluation data; or move to team-based incentives
- **Hiring**: prefer competent-and-social over skilled-loner; best interview = work with the team for a day

## Roles Are Fluid
On a mature team, roles aren't fixed. A programmer can write a story; a project manager can suggest architectural improvements. The goal is each person contributing their best.
